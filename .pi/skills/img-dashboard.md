# IMG Dashboard — Project Skill

## What this project is

The IMG (Instituut Mijnbouwschade Groningen) public dashboard is a data-driven frontend that visualises damage claim statistics. It lives at `img.publikaan.nl` and is developed by a small team. Since 2019 IMG has published weekly public data on damage reports, settlements, payouts, rejection rates, and related schemes (waardedalingsregeling, etc.).

The codebase has gone through at least two major versions. The newer version (`img-new-dashboard`) is the active development target. An older bundle (`dashboard-bundle.js`) still exists and was briefly explored for co-existence with the new version using Shadow DOM or iframe embedding.

## Architecture

The frontend is **TypeScript, config-driven, D3-based**. There is no React or Vue — the DOM is managed manually through controller classes.

### Controller hierarchy

```
DashboardController
  └── PageController         (one per route/topic)
        └── GroupController  (one per data group/section)
              └── GraphController  (one per chart)
```

Each level has a `slug`, a `segment`, and a `config` object. Controllers are instantiated by name from a registry (not hardcoded imports).

### Services

- `DataService` — fetches and caches API data; has `.collection()` and `.clear()`
- `ParamService` — manages URL params, current `topic`, `version`, etc.
- `NavService` — handles routing/navigation

### Segment system

A `segment` is the state object that drives what data is fetched and rendered. It cascades:

```
page.segment → group.segment → graph.segment
```

Each level can override keys from the level above. The cascade is a shallow merge:

```typescript
const graphSegment = {
  ...pageSegment,
  ...groupSegment,
  ...(graph.segment || {})
};
```

Keys in a segment can include: `gemeente`, `periodization`, `key`, `cumulative`, `regeling_code`, `domein_code`, `periode_vanaf`, `periode_totenmet`, etc.

### Config structure (`IPageConfig`)

```typescript
{
  slug: "gemeente",
  segment: {
    gemeente: "Groningen",
    periodization: "monthly"
  },
  groups: [
    {
      slug: "gemeenten_vv",
      ctrlr: "GroupControllerV1",
      segment: { key: "ingediend", cumulative: true },
      graphs: [
        {
          slug: "gemeente_trend_vv",
          ctrlr: "BarTrendV1",
          segment: { cumulative: false }
        }
      ]
    }
  ]
}
```

Configs can also define `endpoints` at page or group level; graphs inherit from their group or page.

### API / endpoints

Endpoints use PostgREST-style query params:

```
/api/v1/resource?gemeente=eq.Groningen&periodization=eq.monthly
```

Placeholders in endpoint strings (`{gemeente}`) are replaced from the segment before fetch. The `DataService.applyParams()` method handles this, prepending `eq.` where no operator prefix is present.

## Patterns to know

### Update flow

Graphs have two methods:
- `update(data, update)` — public, called from group
- `_update(data, update, range?)` — implementation; handles redraw vs full re-render

If a graph controller doesn't override `update()`, nothing happens on filter change. Always check that concrete graph controllers call `_update`.

### `onFilterChange`

Lives on `PageController`. Called when a page-level filter (e.g. gemeente dropdown) changes:

```typescript
async onFilterChange(updates: Partial<Segment>) {
  Object.assign(this.segment, updates);
  // cascade to groups and graphs
  // clear data cache
  // re-gather data
  // call group.ctrlr.update() for each group in chartArray
}
```

### `groups.json`

Generated by the Obsidian plugin. Contains the group/graph config tree. Consumed by the dashboard at build or runtime to register available pages and their chart configs.

### Old dashboard bundle

The old version exports `InitGraph` and auto-initialises on load by looking for `[data-img-graph-preset="dashboard"]`. If you need to embed it inside the new version:
- Shadow DOM isolates styles but not `document.querySelectorAll` — requires patching
- iframe gives full isolation but complicates height management
- Cleanest solution: refactor the old bundle to accept a root element param

## Domain knowledge

- **Schademelding** — damage report filed by a resident
- **Afhandeling** — case resolution (approval, rejection, or settlement)
- **Waardedalingsregeling** — compensation scheme for property value decrease due to earthquakes
  - For woningen (residential): live since Sept 2020, phased by municipality
  - For niet-woningen (commercial/agricultural): opened May 2024, max 12% WOZ-waarde
- **Gemeente** — municipality; a key filter dimension across most pages
- Cijfers (statistics) are published weekly; historical corrections are tracked and published on the dashboard's corrections page
